同一 Vault 与 Profile 的三种运行方式
i
同 Profile：官方 QQ 插件与本插件装在同一 Profile 时，QQ 会话与桌面会话共享同一 Vault 和同一套联动策略（本页的配置对两者都生效）。
!
独立 Profile：如果官方 QQ 插件装在另一个 Profile，需要在该 Profile 里也安装本插件并指向同一个 Vault 路径；本插件不会自动修改任何 Profile 的配置。并发写入依赖既有的 journal / 原子写机制。
!
配置不一致：两个 Profile 指向不同 Vault 时各自独立，记忆不共享。
安全与凭据
AppSecret 不经过本插件
!
官方插件会把 appId/appSecret 以明文 YAML 写入 <profile>/cordis.patch.yml（它自己的实现选择，没有使用系统密钥库）。本插件不读取、不保存、不回显任何凭据，也没有 Secret 输入框。

兼容性：官方声明不等于本机验证
i
官方 package.json 的 dsh.compatibility.dshReleases 只记录了「已验证」的 0.1.0-rc.8 / 0.2.0-rc.2；0.2.1 线不在官方验证范围内。宿主安装门槛可能仍会放行（peer 范围宽松），但「能装」不等于「官方验证过」。
i
本插件仓库声明的宿主兼容范围是 0.2.1-rc.3（engines.dsh：>=0.2.1-rc.3 <0.2.2）。实际运行版本以宿主界面为准，本页不伪造版本号。
i
本插件不实现二维码绑定，也不调用官方的绑定 / 解绑 / 手动提交接口；唯一发起的网络请求是只读探测 GET /qqbot/im-qqbot/bind。
